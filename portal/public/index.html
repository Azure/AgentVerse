Trustworthy AI · Security

Securing agents on Azure

A practical, introductory baseline for building and running agents securely — mapped to the Azure Well-Architected Framework (WAF), the Cloud Adoption Framework (CAF) and Microsoft’s Zero Trust guidance. Each area links to the official Microsoft documentation to go deeper. This is a starting baseline, not a complete security architecture — always threat-model your own workload.

WAF · AI design principles ↗ CAF · Govern & secure agents ↗
🔑

Identity & least privilege

  • Give every agent its own Microsoft Entra Agent ID — never share identities between agents (some Agent ID capabilities are in preview).
  • Separate the agent’s workload identity from delegated user authorization; grant only the scopes each task needs.
  • Extend Zero Trust: Conditional Access, risk-based policies and periodic access reviews.
Entra Agent ID best practices ↗ Entra Agent ID docs ↗
📜

Governance & lifecycle

  • Every agent has a business sponsor and a technical owner.
  • Keep a central inventory; standardize deploy, patch and retire/revoke flows to avoid orphaned agents.
  • Enforce a single security baseline aligned to Responsible AI (fairness, transparency, accountability).
CAF · Govern & secure agents ↗
🛡

Prompt & content safety

  • Screen input with Prompt Shields for direct and indirect (cross-prompt) injection — treat it as a detection layer, not a hard security boundary.
  • Keep harmful-content filtering separate from prompt-injection, authorization and data-exfiltration controls.
  • Treat all RAG / grounding documents and tool outputs as untrusted input.
Prompt Shields (Content Safety) ↗
🔒

Data protection & grounding

  • Least-privilege data access; encrypt in transit and at rest.
  • Apply DLP and insider-risk controls with Microsoft Purview; respect residency and compliance.
  • Protect agent memory, vector stores, caches and embeddings — they can leak sensitive data.
CAF · Data governance ↗
🏗

Secure application design

  • Centralize policy at an AI gateway; isolate/containerize components.
  • Require per-action authorization and human approval for consequential actions.
  • Restrict network egress, manage secrets in Key Vault, and vet tool / MCP / plugin supply chain.
WAF · AI application design ↗ WAF · AI design principles ↗
📈

Observability & threat detection

  • Trace agent decisions and tool calls with Application Insights and Log Analytics.
  • Detect threats with Microsoft Defender; red-team and evaluate adversarially before and after release.
  • Redact prompts, responses, tool arguments, secrets and retrieved data in logs; set retention controls. Plan incident response and safe shutdown/revocation.
